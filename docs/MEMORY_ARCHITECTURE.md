# Memory & Second Brain Architecture

This is AEON's long-term value layer. Every document, note, and conversation enriches the system over time.

## Data Flow

```
User uploads file (Files block)
        │
        ▼
  /api/fs/upload
        │
        ├── Saved to Data/Second_Brain/
        │
        ▼
  Incremental re-index (automatic)
        │
        ▼
  brain-data.json updated
        │
        ▼
  Second Brain matrix shows new node
        │
        ▼
  All blocks can reference it via /api/brain_file
```

## Three Memory Systems

### 1. Second Brain (Document Matrix)
- **Storage:** `Data/Second_Brain/` folder structure
- **Index:** `src/brain-data.json` (generated by `tools/incremental-index.js`)
- **Cloud sync:** Supabase `documents` table (content + metadata)
- **Access:** `/api/brain_file?nodeId=...` returns file content
- **Visual:** 3D force-directed graph (NeuronViewport component)
- **Formats:** .md, .txt, .json, .pdf, .docx, .html, .css, .js

### 2. Memory Block (Structured Facts)
- **Storage:** Local JSON via `/api/memory` + Supabase `aeon_blocks.memory`
- **Categories:** fact, identity, preference, contact, project, goal, task
- **Features:** Pin, search, bulk delete, import/export, LLM-powered tidy (dedup)
- **Access:** `/api/memory` (list), `/api/memory/add`, `/api/memory/:id` (CRUD)

### 3. Chat History + Audit Trail
- **Storage:** `chat_log.json` + `audit_log.json` (local) + Supabase tables
- **Purpose:** Conversation memory, action logging, telemetry
- **Access:** `/api/chat` (CRUD), `/api/audit` (append + read)

## Indexing

### Full Index (`npm run index`)
- Walks entire `Data/Second_Brain/` tree recursively
- Extracts text from .md, .txt, .json, .pdf (via pdf-parse), .docx (via mammoth)
- Generates node graph with folder hierarchy
- Outputs `src/brain-data.json`

### Incremental Index (`tools/incremental-index.js`)
- Runs at boot via `launch-brain.bat`
- Triggered after file uploads to Second_Brain directory
- Compares file hashes against `.sync-manifest.json`
- Only processes new/modified/deleted files

## Cloud Sync

### Supabase Tables
- `documents` — Full document content + metadata (original_id, title, source)
- `aeon_blocks` with `block_tag='brain_graph'` — Node graph for cloud visualization
- `aeon_blocks` with `block_tag='memory'` — Structured memory entries

### Sync Pattern
Every component that reads Second Brain data follows:
```
1. Try local API (/api/brain_file, /api/notes, etc.)
2. If local fails → query Supabase directly
3. If Supabase fails → show empty state
```

## What Makes This Valuable

For a solo operator: your entire knowledge base is searchable and AI-queryable.

For an organization: employee records, SOPs, client notes, meeting summaries, decisions — all indexed and connected. Every block gets smarter because it can reference the full document corpus.

The switching cost increases with every document added. That's the moat.
